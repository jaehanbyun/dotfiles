# Obsidian Vault

자주 호출되는 전역 라우터다. 콘텐츠 구조를 강제하지 말고, 대상 vault를 정확히 선택하며 안전하게 작업하는 데 집중한다.

## 적용 범위

- 사용자가 Obsidian 또는 vault를 명시했거나, 현재 문맥에서 기록 대상이 Obsidian으로 명확할 때 적용한다.
- 일반 코드 저장소의 Markdown 파일, 일반적인 태그, README 작업만으로는 적용하지 않는다.
- 기사, PDF, YouTube, 업무 로그처럼 더 구체적인 Obsidian 스킬이 있으면 그 스킬이 작업 절차를 담당하고, 이 스킬은 vault 선택과 안전 규칙만 제공한다.

## 대상 vault 확정

작업 전에 `obsidian vaults verbose`로 등록된 vault를 확인하고 다음 순서로 대상을 결정한다.

1. 사용자가 지정한 vault 이름 또는 경로
2. 현재 작업 문맥에서 명시된 vault
3. 설정되어 있다면 `$OBSIDIAN_DEFAULT_VAULT`
4. `$VAULT_ROOT`가 등록된 vault 경로 하나와 정확히 일치하면 해당 vault

대상을 하나로 확정할 수 없으면:

- 쓰기 작업은 추측하지 말고 사용자에게 vault를 묻는다.
- 읽기 작업도 여러 vault의 결과를 임의로 섞지 말고 범위를 명시하거나 묻는다.

활성 vault에는 의존하지 않는다. 모든 Obsidian CLI 호출에서 전역 옵션을 명령 앞에 둔다.

```bash
obsidian vault="<vault-name>" <command> [options]
```

## 도구 선택

1. **기본: `obsidian` CLI**
   - 읽기, 검색, 생성, 추가, daily note
   - 태그, 백링크, 미해결 링크, 속성, tasks
   - 이동과 이름 변경
2. **보조: `rg`와 일반 파일 도구**
   - 단순 텍스트 검색
   - CLI가 표현하기 어려운 정밀 Markdown 수정
   - 수정 전 범위 확인
3. **선택적 도구**
   - LSP, MCP, 시맨틱 검색기는 사용자가 요청했거나 CLI로 부족한 작업에만 사용한다.
   - 먼저 현재 세션에서 실제 사용 가능한지 확인한다.
   - `vis`라는 이름이 원하는 Vault 검색기라고 가정하지 않는다.

## 변경 안전 규칙

- 읽기, 설명, 검색, 진단 요청은 vault 파일을 변경하지 않는다.
- 사용자가 명시적으로 요청한 범위의 생성, 추가, 수정은 다시 확인하지 않고 수행할 수 있다.
- 수정 전 대상 노트와 필요한 경우 같은 폴더의 인접 노트 또는 템플릿을 읽는다.
- 기존 frontmatter, wiki-link, embed, callout, 태그, 제목 규칙을 보존한다.
- 이동과 이름 변경은 링크 갱신을 위해 `obsidian move` 또는 `obsidian rename`을 우선한다.
- 삭제, 영구 삭제, 덮어쓰기, 대량 변경, 플러그인·테마·동기화 설정 변경은 명시적 요청과 정확한 대상을 확인한 뒤 수행한다.
- `.obsidian/`, `archive/`, 첨부 파일, 이미지, `.canvas`는 기본 처리 범위에서 제외하되 사용자가 명시하면 다룰 수 있다.
- 오류가 나면 자동으로 로그 파일을 만들지 말고 실패한 대상과 원인을 보고한다.

## Vault 관례

- 전역 폴더 구조, 태그 체계, frontmatter 스키마를 새로 강제하지 않는다.
- 넓은 작업은 관련 MOC, 폴더, 검색 결과부터 확인하고 필요한 범위만 점진적으로 확장한다.

## 완료 보고

변경 작업 후에는 대상 vault, 생성·수정·이동한 파일, 수행한 검증을 짧게 보고한다. 일부 작업이 실패했다면 파일을 새로 만들지 말고 남은 대상과 이유를 함께 알린다.
