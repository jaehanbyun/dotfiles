# 캐릭터 쇼츠 제작

목표는 **이미지 3장 → Hailuo 15초 영상 2개 → CapCut 완성 영상 1개**다. 스킬 작성·수정 요청 자체는 새 제작 실행 요청이 아니다. 제작 요청일 때 실행하며 기존 결과가 있으면 해당 단계부터 재개한다.

## 입력과 실행 상태

- 입력은 캐릭터 설명 또는 참조, 재사용할 자산, 명시된 품질·크레딧·재시도 예산이다. 디자인의 핵심은 **미소녀풍의 성인 여성 · 섹시함 · 개성**이며, 이 키워드만 주어져도 어울리는 새 콘셉트를 설계해 간단히 설명하고 진행한다. 새 캐릭터 요청에서 이전 인물의 외형을 자동 재사용하지 않는다. 같은 캐릭터를 이어달라는 요청이나 외형 참조가 있을 때 해당 인물을 유지한다. 단순 취향 예시 이미지를 복제할 캐릭터로 혼동하지 않는다.
- 기본 구성: 성인 1명, 세로 9:16 영상, 각 15초, **타임랩스 → 패션 필름**, MP4/H.264, 원본 해상도와 FPS 유지. 이전의 2K/24fps는 원본이 1440×2560/24fps였기 때문이며 모든 입력에 강제하지 않는다.
- Hailuo에서는 사용자 현지 시간대의 **작업 시작 날짜 `YYYY-MM-DD`를 프로젝트명으로 사용**하고 해당 프로젝트 안에서 두 영상을 제작한다. 시작 날짜를 실행 상태에 저장해 자정 이후 재개해도 같은 프로젝트를 사용한다.
- `outputs/<run-name>/`에 선택된 이미지·원본 영상·완성본을 보관하고 `work/<run-name>/`에 중간물·QA·실행 상태를 둔다. 기존 결과를 덮어쓰지 않는 실행 이름을 사용한다.
- `work/<run-name>/run.json`에 캐릭터 명세, 자산 절대 경로/역할, 사용한 프롬프트 경로, Hailuo 모델/설정/표시된 비용/작업 ID·URL·상태, 다운로드 경로, CapCut 프로젝트명, 연결 순서, 출력 사양과 검증 결과를 단계마다 기록한다. 미확인 값은 null과 이유로 남기고 계정 비밀정보는 기록하지 않는다.

## 1. 동일 캐릭터 이미지 3종

이미지를 생성할 때 설치된 `imagegen` 스킬을 읽고 기본 내장 이미지 도구를 사용한다. 로컬 참조는 먼저 시각적으로 확인한다. [references/image-prompts.md](references/image-prompts.md)를 읽는다.

새 제작 건마다 헤어, 얼굴, 체형의 균형, 의상 실루엣, 표정, 색감, 배경, 2D 일러스트의 표현 방식을 유연하게 설계한다. 은발 단발·검은 가죽·고딕·어두운 배경·따뜻한 역광은 필수 조건이 아니다. **제작 건 사이의 다양성**과 **한 제작 건의 3장 사이 일관성**을 구분한다.

1. `01-upper-flat.png`: 담백한 채색 상반신. 깨끗한 선화·기본색·절제된 명암이 있고 강한 광택과 복잡한 그라데이션은 없다.
2. `02-upper-rendered.png`: 01을 편집 대상으로 삼아 **채색·조명·재질만** 고도화한다. 얼굴, 체형, 포즈, 프레이밍, 선화, 헤어와 의상·장신구의 위치를 유지한다.
3. `03-full-flat.png`: 01과 같은 인물을 머리부터 신발까지 확장한다. 담백한 채색을 유지하고, 보이지 않던 하의·신발은 캐릭터에 맞게 설계해 이후 고정한다.

별도 이미지 3장으로 저장하고 모두 확인한다. 두 상반신의 인물/구도가 바뀌거나 전신이 잘리면 해당 자산만 수정한다. 담백한 채색을 선화만 남은 이미지나 저품질 이미지로 해석하지 않는다. 콜라주를 만들지 않는다.

## 2. Hailuo 영상 생성

`aside-browser` 스킬과 현재 `aside guide` 지침으로 브라우저를 제어한다. 기존 영상 재사용 시에도 현재 목록에서 항목을 확인한다. 과거 모델명, 비용, 탭 ID, 카드 순서, 세션 ID를 고정하지 않는다.

- **생성 전에 날짜 프로젝트부터 준비한다.** 현재 날짜를 확인하고 `YYYY-MM-DD` 프로젝트를 찾는다. 없으면 생성하고, 있으면 그 안에 이번 작업을 구분해 추가한다. 재개 시 기록된 프로젝트 ID/URL로 돌아가며 이름이 같다는 이유로 중복 프로젝트를 만들지 않는다. 제목과 실제 프로젝트 진입 화면을 확인하고 `run.json`의 hailuo에 project_name/project_id/project_url/work_date/timezone을 기록한다. 기존 프로젝트나 영상을 삭제·덮어쓰지 않는다.
- 이미지 참조 업로드와 두 영상 생성은 모두 그 프로젝트 안에서 수행한다. 생성 목록에서 두 작업이 해당 프로젝트 소속인지 확인한다. UI가 프로젝트를 지원하지 않거나 접근할 수 없다면 확인한 한계를 설명하고 대안을 요청한다. 일반 생성 목록을 프로젝트라고 부르거나 지정된 프로젝트 밖에서 조용히 생성하지 않는다.

- 제작 요청에 포함된 참조 업로드·영상 생성은 진행한다. 현재 모델의 길이/참조 지원/표시 비용을 확인하고 명시된 예산을 지킨다. 별도 재시도 예산이 없으면 각 영상 1회 생성 후 평가하며, 추가 유료 재생성은 문제와 비용을 제시해 요청한다. 응답이 불확실하면 기존 작업 유무부터 확인한다. 구독·크레딧 구매는 제작 요청에 포함된 것으로 간주하지 않는다.
- **타임랩스:** 01과 02를 중간 채색 목표와 최종 목표인 **참조 자산**으로 첨부하고 [references/timelapse-prompt.md](references/timelapse-prompt.md)의 사용자 원문을 사용한다. 첫 프레임은 빈 캔버스다. 01을 강제 시작 프레임 슬롯에 넣지 않는다. 현재 모드가 목표 참조와 시작 프레임을 구별할 수 없다면 생성 전에 멈추고, 다른 참조 모드 또는 별도 빈 캔버스 시작 이미지가 필요한지 설명한다. 프롬프트로 강제 시작 프레임을 덮어쓸 수 있다고 약속하지 않는다.
- **패션 필름:** 03을 캐릭터 참조로 연결하고 [references/fashion-prompt.md](references/fashion-prompt.md)의 사용자 원문을 사용한다. `@[char ref]`를 실제 업로드 자산에 연결한다. 일반 문자열만 넣고 참조 연결이 완료됐다고 판단하지 않는다. 10포즈/15초/140 BPM/참조 화풍 유지 조건을 보존한다.
- 각 작업의 ID와 역할을 기록하고 완료를 기다린다. 목록 정렬이 바뀌어도 역할을 뒤바꾸거나 대기 중 중복 제출하지 않는다.
- 타임랩스는 빈 첫 화면, 스케치→선화→플랫색→렌더링 과정, 완성 후에만 미세한 움직임이 있는지 확인한다. 패션은 동일 인물·복장·참조 화풍, 구분되는 10포즈, 해부학, 오디오를 확인한다. 결과의 불일치를 기록한다. 프롬프트에 적힌 조건을 생성물이 충족했다고 자동 간주하지 않는다.

## 3. 공식 다운로드와 CapCut 편집

[references/capcut-workflow.md](references/capcut-workflow.md)를 읽는다.

- Hailuo 공식 **워터마크 없이** 옵션으로 다운로드한다. 옵션이 없거나 업그레이드가 필요하면 알리고 워터마크 크롭/제거 또는 결제로 대신하지 않는다.
- 다운로드 완료와 실제 파일을 확인해 `04-timelapse.mp4`, `05-fashion.mp4`로 저장한다. Aside 세션에 저장됐다면 실제 반환 경로에서 작업 폴더로 복사한 후 편집에 사용한다.
- 설치된 CapCut의 새 프로젝트에서 두 파일을 메인 트랙에 순서대로, 간격·중첩 없이 연결한다. 별도 요청이 없다면 전환 효과·자막·음악을 추가하지 않고 원본 오디오를 유지한다.
- 원본에 맞는 해상도·FPS, MP4/H.264로 `06-final.mp4`를 내보낸다. 화면에서 경로/옵션을 확인하고 저장 완료를 기다린다. 동의하지 않은 클라우드 동기화나 SNS 공유는 실행하지 않는다.
- UI가 막히면 최신 상태를 읽고 AX/화면 좌표 중 다른 방식을 한 번 시도한다. 같은 드롭다운 오류를 반복하지 않는다. 편집을 저장하고 필요한 특정 설정만 사용자에게 요청한다. 사용자가 완료했다고 하면 화면을 다시 확인하고 남은 작업을 이어간다.

## 4. 검증과 전달

아래 스크립트에 소스를 **편집 순서**로 지정한다. FPS는 실제 의도한 출력값으로 바꾼다.

```bash
python3 <skill-dir>/scripts/verify_video.py \
  --video <run-output>/06-final.mp4 \
  --sources <run-output>/04-timelapse.mp4 <run-output>/05-fashion.mp4 \
  --expected-fps 24 --report-dir <run-work>/qa
```

전체 디코딩, 길이, 해상도·FPS·오디오 유무를 검사하고 주요 시점과 연결 전후 프레임을 만든다. **자동 검사만으로 순서·워터마크·포즈·음질을 확인했다고 말하지 않는다.** 프레임을 열어 실제 순서·공백·로고를 확인하고 오디오는 재생 가능한 도구로 듣는다. 들을 수 없으면 검증 범위를 명시한다.

완료 조건: 이미지 3장 및 공식 원본 영상 2개 저장, CapCut 순서 확인, 완성 파일 존재/전체 디코딩 성공, 실제 길이·사양 확인, 시각 QA 완료. 미확인 조건이나 원본 결함은 밝힌다. 완성 영상 링크를 먼저 제공하고 이미지/프로젝트명은 짧게 덧붙인다. 채널 개설·SNS 업로드는 별도 요청 범위다.

예시: `$hailuo-character-shorts 이 참조 캐릭터로 이미지 3종부터 두 영상 생성, 캡컷 연결까지 진행해줘. 유료 재생성은 하지 마.`
