# 다운로드·CapCut 실행 메모

2026-09-07의 실제 실행에서 관찰한 경로다. UI는 달라질 수 있으므로 좌표나 AX 인덱스를 복사하지 않는다.

## Hailuo 날짜 프로젝트 생성

2026-09-07 관찰: 생성 작업 화면 상단의 현재 프로젝트명 버튼을 열면 `최근 프로젝트` 목록과 작은 `+` 버튼이 나타났다. `+` → `New Project` 입력란에 작업 날짜 입력 → Enter로 새 프로젝트가 생성되고 상단 제목이 바뀌었다. 자산의 프로젝트 목록에는 생성 버튼이 명확히 보이지 않을 수 있으므로 생성 작업 화면의 프로젝트 선택기를 확인한다. 기존 `Default Project`의 내용을 지우거나 이름을 바꾸는 작업과 구별한다. 영상/이미지 모드 전환 후에도 선택한 날짜 프로젝트명이 유지되는지 확인한다. 브라우저 URL의 projectId가 바로 갱신되지 않는 경우 ID를 추측하지 말고 현재 프로젝트 제목과 생성 결과의 소속을 확인한다.

참조 업로드 시 `옴니 참조 가이드`가 나타날 수 있다. 확인 버튼이 단순 안내 닫기인지, 기능 이용약관 동의인지는 본문으로 구별한다. 새 약관 동의가 필요한 경우 실제 조항을 간단히 설명하고 사용자 확인을 받은 후 이어간다.

## 공식 다운로드

Hailuo 생성 목록의 각 항목에서 다운로드 메뉴 → `워터마크 없이`를 선택했을 때 공식 파일이 내려왔다. 역할/작업 ID를 먼저 기록하고 다운로드 완료 및 실제 파일 크기·ffprobe를 확인한다. Aside가 자기 세션 artifacts에만 저장할 수 있으면 반환 경로에서 영구 작업 폴더로 복사한다. 로그인/다운로드 URL이나 임시 세션 경로를 고정하지 않는다.

## CapCut

직접 제공된 CapCut 기능이 있으면 우선 사용하고, 없으면 CUA native app API로 제어한다. API 문서를 읽고 `getApp("CapCut")`으로 현재 창을 확인한다. UI 작업마다 상태를 갱신한다. 브라우저 에이전트에 native 앱 조작까지 맡기지 않는다.

- 새 프로젝트 생성 → 알아보기 쉬운 실행 이름으로 변경.
- 두 영상을 파일로 가져온다. macOS 파일 선택에서는 Cmd+Shift+G로 절대 경로를 입력할 수 있었다. 폴더가 가져와졌다면 미디어 폴더를 열고 해당 파일만 추가한다.
- 미디어 썸네일의 우측 하단 추가 버튼으로 메인 트랙에 추가할 수 있었다. 드래그가 실제로 추가됐는지는 클립 라벨과 길이로 확인한다.
- 타임랩스 뒤에 패션 클립을 넣는다. 첫 클립 끝에 재생 헤드를 두고 추가한 후 별도 레이어/겹침이 아닌 연속된 메인 트랙인지 확인한다.
- 기존 프로젝트가 열려 있으면 내용을 지우지 않는다. 해당 프로젝트 재개 요청일 때만 수정한다.
- 내보내기 창의 경로, 해상도, FPS, MP4/H.264를 확인한다. 기본값이 MOV/1080p/30fps일 수 있다. 원본 오디오는 유지하며, `내보낸 동영상을 공간에 동기화`가 켜져 있다면 로컬 출력 요청에 맞게 끈다.
- 저장 완료 후 TikTok/YouTube 공유 창은 게시 성공을 뜻하지 않는다. 로컬 저장을 확인하고 공유 버튼은 누르지 않는다.

## UI 장애와 재개

AX 버튼 클릭이 포커스만 바꾸고 작동하지 않았으나 최신 화면의 실제 버튼 좌표 클릭으로 실행된 사례가 있었다. 내보내기 드롭다운은 클릭해도 값이 바뀌지 않았고 키보드/드래그/좌표 반복도 해결하지 못했다. 캡처 크기가 바뀌면 이전 좌표는 무효다.

한 번의 상태 새로고침과 다른 입력 방식으로 해결되지 않으면 편집을 보존하고 필요한 설정만 요청한다. 예: “내보내기 창에서 2K·mp4·24fps를 선택하고 완료라고 알려주세요.” 실제 필요한 사양으로 바꿔 요청한다. 이전 실행에서는 사용자가 옵션만 선택한 후 에이전트가 내보내기와 QA를 끝냈다. 이 구간을 해결된 완전 무인 자동화로 표현하지 않는다.

CapCut이 지정됐을 때 ffmpeg로 몰래 편집을 대체하지 않는다. ffmpeg는 검증/프레임 추출 용도로 사용할 수 있다. 다른 편집 경로는 사용자가 변경을 허용했을 때만 사용한다.
