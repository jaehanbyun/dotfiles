# 세션 리캡

현재 thread의 맥락을 빠르게 다시 파악할 수 있도록 작업 상태와 다음 행동을 한국어로 정리한다. 전체 대화를 반복하지 말고 재진입에 필요한 정보만 제공한다.

## 출력 원칙

- 현재 대화와 확인된 파일·도구 결과에 근거해 작성한다. 확인되지 않은 내용은 추측하지 말고 `확인되지 않음`으로 표시한다.
- 완료된 일, 진행 중인 일, 막힌 일을 구분한다.
- 사용자의 원래 목표와 이후에 합의된 결정사항을 우선한다.
- 작업 범위가 코드가 아니면 `중요 파일/범위`를 해당 대화·문서·링크·결정으로 바꿔 적는다.
- 짧고 훑어보기 쉽게 작성한다. 불필요한 배경 설명, 전체 transcript 재현, 장황한 분석은 생략한다.
- 다음 행동은 한 번에 시작할 수 있는 구체적인 동사형 문장으로 쓴다.

## 기본 형식

다음 형식을 기본으로 사용한다. 해당하지 않는 항목은 `없음` 또는 `확인되지 않음`으로 짧게 표시한다.

## 세션 리캡

### 현재 작업
- [현재 핵심 목표와 상태]

### 핵심 제약/요구사항
- [반드시 지켜야 할 요구사항과 제약]

### 중요한 파일/범위
- [관련 파일, 산출물, 문서, 링크 또는 작업 범위]

### 이미 내린 결정
- [확정된 선택과 그 이유가 중요한 경우의 짧은 설명]

### 진행 상황
- 완료: [완료된 작업]
- 진행 중: [현재 진행 중인 작업]
- 막힘/대기: [사용자 입력, 외부 상태 또는 오류로 막힌 작업]

### 다음 권장 단계
1. [가장 먼저 실행할 구체적인 행동]
2. [그다음 행동이 있을 때만 추가]

## 예외 처리

- 현재 thread가 새 대화이거나 요약할 작업이 없으면 그 사실을 먼저 말하고, 확인 가능한 최근 요청만 요약한다.
- 사용자가 단순히 “recap”이라고만 하면 위 기본 형식을 사용한다.
- 사용자가 특정 범위나 언어를 지정하면 그 요청을 우선하되, 기본적으로 한국어를 사용한다.
